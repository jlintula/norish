# v0.24.0-beta

## Summary

The layer that pushes changes to open browsers was rebuilt from the ground up.
Nothing looks different; what changes is what happens around the edges: a
browser that lost its connection for a moment gets what it missed, a restart
no longer stalls, and a server holds the same handful of Redis connections
no matter how many tabs a household has open.

## Fixes and Improvements

- A browser that was briefly disconnected — a phone through a tunnel, a laptop
  lid closed for a minute — receives the changes it missed when it comes back,
  in order and without a reload, instead of waiting for the next full refresh.
- Restarting the server with browsers connected now completes in seconds. Every
  open socket is told the server is restarting and the browsers reconnect once
  it is back. Before, a restart waited out a thirty-second timeout for sockets
  it never closed.
- The server's Redis connections no longer grow with the number of open
  browser tabs.
- A grocery change that failed validation now tells only the person who made
  it, not the whole household.
- The startup banner prints the WebSocket path the server actually serves.

## Upgrade notes

- **The WebSocket now checks the browser's `Origin`.** An upgrade from an
  origin other than `AUTH_URL`, an entry of `TRUSTED_ORIGINS` or the request's
  own host is refused with `403`. Most setups need nothing; if your reverse
  proxy rewrites `Host` so the browser's origin is not the one in `AUTH_URL`,
  list the public origin in `TRUSTED_ORIGINS`. The new
  [WebSocket & realtime](../configuration/websocket.md) page has the proxy
  snippets for nginx, Caddy and Traefik, and the idle timeout the proxy must
  exceed.
- **The mobile app is parked.** It is not supported on this release: it is
  expected to break against this server until its own rewrite ships. Use the
  web app on a phone in the meantime.
